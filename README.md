# เว็บค้นหาข้อมูลจาก Google Sheet (หลายไฟล์)

โครงสร้างโปรเจกต์:

```
sheet-search/
├── backend/
│   └── Code.gs        # Apps Script โปรเจกต์แยกต่างหาก (standalone) — รู้จักหลายไฟล์ผ่าน SPREADSHEETS
└── frontend/
    ├── index.html      # หน้าเว็บหลัก (เลือกไฟล์ → เลือกแท็บ → ดู/เพิ่ม/ลบข้อมูล)
    ├── style.css       # ดีไซน์
    ├── script.js       # เรียก API และแสดงผลลัพธ์
    └── config.js       # ใส่ URL ของ API และรหัสเข้าถึง
```

## ภาพรวมสถาปัตยกรรม

GitHub Pages โฮสต์ได้เฉพาะไฟล์ static (HTML/CSS/JS) จึงรัน Google Apps Script บนนั้นไม่ได้โดยตรง
วิธีที่ใช้งานได้คือแยกสองส่วน:

1. **Backend** — Apps Script โปรเจกต์แยกต่างหาก (ไม่ผูกกับไฟล์ Sheet) เปิดไฟล์ตามรายการใน `SPREADSHEETS` ด้วย `SpreadsheetApp.openById()` deploy เป็น Web App จะได้ URL สำหรับเรียกแบบ API
2. **Frontend** — ไฟล์ static ใน `frontend/` วางบน GitHub Pages แล้วเรียก URL จากข้อ 1 ผ่านเทคนิค JSONP (ไม่ใช้ `fetch()` เพราะ Apps Script ไม่ส่ง CORS header กลับมา)

**เรื่องสิทธิ์การเข้าถึง:** ใช้ **รหัสเข้าถึงแบบรหัสลับ (access key)** แทนการล็อกอินด้วย Google เพราะการล็อกอินทำให้เกิดปัญหา CORS/redirect เมื่อเรียกข้ามโดเมน

## หน้าเว็บในระบบ

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | หน้าหลัก — ค้นหา เพิ่ม แก้ไข ลบ กู้คืน Dashboard รายงานย้อนหลัง |
| `status.html` | หน้ารายละเอียดตามสถานะ — เปิดจากการคลิกสถานะใน Dashboard (เปิดแท็บใหม่) บอกว่าสถานะนั้นอยู่ไฟล์ไหน แท็บไหน กี่เคส พร้อมรายการเคสทั้งหมดและดาวน์โหลด Excel |

ทั้งสองหน้าใช้ `style.css` และ `config.js` ร่วมกัน และต้องวางไว้ที่ **root ของ repo ระดับเดียวกันทั้งหมด**

## กลไกสำคัญที่ควรรู้ก่อนแก้โค้ด

- **ลายนิ้วมือแถว (`rowFingerprint_`)** — ก่อนลบหรือแก้ไข ระบบจะเทียบค่าทุกเซลล์ของแถวนั้นกับที่หน้าเว็บเห็น ถ้าไม่ตรงจะหยุดทันที กันการเขียนทับผิดแถวเมื่อมีคนอื่นลบแถวข้างบนไปแล้ว **สูตรนี้ต้องเหมือนกันเป๊ะทั้งใน `Code.gs` และ `script.js`**
- **การคัดลอก Dropdown** — ต้องใช้ `copyTo` แบบ `PASTE_DATA_VALIDATION` เท่านั้น ห้ามใช้ `setDataValidations` เพราะ Apps Script อ่านสีของตัวเลือกไม่ได้ สีจะหายหมด
- **ล็อกกันเขียนทับกัน** — คำสั่งที่เขียนข้อมูลทุกตัวอยู่ใน `WRITE_ACTIONS` และถูกครอบด้วย `LockService` เพิ่ม action ใหม่ที่เขียนข้อมูลต้องเพิ่มชื่อเข้าลิสต์นี้ด้วย
- **Log แยกเป็นแท็บรายปี** — เขียนลงแท็บของปีปัจจุบันเสมอ ส่วนการอ่านใช้ `readLogRows_()` ซึ่งรวมทุกแท็บให้ (รวมแท็บเดิมก่อนแยกรายปี) และข้ามแท็บปีที่อยู่นอกช่วงที่ขอ

ดูกฎเพิ่มเติมสำหรับคนที่จะมาแก้โค้ดต่อได้ที่ไฟล์ `CLAUDE.md`

## หน้าตาการใช้งาน (3 ขั้น)

1. **เลือกไฟล์** — หน้าแรกโชว์การ์ดรายชื่อไฟล์ทั้งหมด โหลดเร็วเพราะไม่แตะเนื้อหาในชีตเลย ใต้รายการมีหัวข้อ **"เพิ่มชีทใหม่"** พร้อมฟอร์มให้กรอกชื่อ + ลิงก์ Google Sheet เพื่อเพิ่มไฟล์เข้าระบบได้ทันทีโดยไม่ต้องแก้โค้ดหรือ Deploy ใหม่ และปุ่ม **"🗑 ถังขยะไฟล์"** สำหรับกู้คืนไฟล์ที่เคยเอาออกจากระบบ (กด × ที่มุมการ์ดไฟล์เพื่อเอาออก)
2. **เลือกแท็บ** — กดเข้าไฟล์แล้วเห็นทุกแท็บในไฟล์นั้นเป็นปุ่มให้เลือก
3. **ดู/เพิ่ม/ลบข้อมูล** — เลือกแท็บแล้วค้นหาได้ตามปกติ พร้อมปุ่ม "+ เพิ่มข้อมูล" และ "จัดการคอลัมน์" (ลบทั้งคอลัมน์) และปุ่มถังขยะที่แต่ละการ์ดผลลัพธ์ (ลบทั้งแถว) ทุกการลบมีระบบถังขยะให้กู้คืนได้ผ่านปุ่ม "🗑 ถังขยะ"

## ขั้นตอนที่ 1: ตั้งค่า Backend (Apps Script)

1. ไปที่ **script.google.com** → กด **New project**
2. ลบโค้ดตัวอย่างเดิมออกให้หมด (รวมถึงบรรทัด `function myFunction() {}`) แล้ววางโค้ดจาก `backend/Code.gs` แทน
3. รายชื่อไฟล์ตอนนี้เก็บอยู่ใน **Script Properties** ไม่ใช่โค้ดอีกต่อไป (ดูข้อ 4) — ค่า `DEFAULT_SPREADSHEETS` ในโค้ดจะถูกใช้แค่ครั้งแรกที่รันเท่านั้น เพิ่มไฟล์ใหม่ทีหลังทำผ่านปุ่ม "+ เพิ่มไฟล์ใหม่" บนหน้าเว็บได้เลย ไม่ต้องแก้ตรงนี้อีก
4. ไปที่ **Project Settings** (ไอคอนรูปเฟือง) → **Script Properties** → เพิ่ม property ชื่อ `DASHBOARD_ACCESS_KEY` ค่าเป็นรหัสลับที่ตั้งเอง
4.1. เพิ่ม property ชื่อ `ALLOWED_EMAILS` ค่าเป็นรายชื่ออีเมล Gmail ที่อนุญาตให้เข้าใช้งาน คั่นด้วย comma เช่น `beer.online2013@gmail.com,someone@gmail.com`
4.2. เพิ่ม property ชื่อ `GOOGLE_CLIENT_ID` ค่าเป็น Client ID ที่ได้จากขั้นตอน **"ตั้งค่าล็อกอินด้วย Google"** ด้านล่าง (ทำขั้นตอนนั้นก่อนแล้วย้อนกลับมาใส่ค่านี้ก็ได้)
5. กด **Deploy > New deployment**
   - เลือกประเภท **Web app**
   - **Execute as: Me**
   - **Who has access: Anyone**
6. กด Deploy → กด Allow เมื่อขึ้นหน้าขอสิทธิ์
7. คัดลอก **Web app URL** ที่ได้

**เมื่อแก้โค้ดในอนาคต:** ต้องกลับไปที่ **Deploy > Manage deployments** → แก้ไข **รายการเดิมที่ URL ตรงกับใน config.js** → เปลี่ยน Version เป็น **New version** → Deploy ทุกครั้ง (แค่กด Save ในหน้า Editor ไม่พอ ลิงก์ที่ใช้งานจริงจะไม่อัปเดตโค้ดตาม)

## ขั้นตอนที่ 2: ตั้งค่า Frontend

เปิดไฟล์ `frontend/config.js` แล้วใส่ค่า 2 ตัว:

```js
const API_URL = 'https://script.google.com/macros/s/xxxxx/exec';
const ACCESS_KEY = 'รหัสลับเดียวกับที่ตั้งใน DASHBOARD_ACCESS_KEY';
const GOOGLE_CLIENT_ID = 'xxxxx.apps.googleusercontent.com'; // จากขั้นตอน "ตั้งค่าล็อกอินด้วย Google" ด้านล่าง
```

**ข้อควรรู้เรื่องความปลอดภัย:** การเข้าสู่ระบบยืนยันตัวตนจริงกับ Google แล้วออก **ตั๋วเข้าใช้งาน (session token)** ที่เซ็นลายเซ็นด้วยกุญแจลับ (HMAC-SHA256) ซึ่งเก็บอยู่ใน Script Properties เท่านั้น ไม่เคยส่งออกมาฝั่งหน้าเว็บ — ทุกคำสั่งหลังจากนั้นต้องแนบตั๋วนี้ และ **ชื่อผู้แก้ไขที่บันทึกใน Log ดึงจากตั๋วเสมอ ปลอมไม่ได้** ตั๋วมีอายุ 7 วัน และยังตรวจกับรายชื่อ `ALLOWED_EMAILS` ทุกครั้ง เผื่อมีคนถูกถอนสิทธิ์ไปแล้ว

ส่วนรหัสลับ `ACCESS_KEY` ยังฝังอยู่ในไฟล์ JavaScript ฝั่ง frontend ใครเปิดดูโค้ดหน้าเว็บ (View Source) ก็เห็นได้ — แต่ลำพังรหัสนี้ใช้อะไรไม่ได้ เพราะทุกคำสั่งต้องมีตั๋วที่ยืนยันกับ Google แล้วด้วย เหมาะกับการใช้งานภายในทีม ไม่ใช่ระดับความปลอดภัยแบบธนาคาร

## ขั้นตอนที่ 3: อัปโหลดขึ้น GitHub Pages

1. อัปโหลดไฟล์ในโฟลเดอร์ `frontend/` ทั้งหมด (`index.html`, `style.css`, `script.js`, `config.js` ที่ใส่ค่าแล้ว) ไว้ที่ root ของ repo (ทับของเดิม)
2. รอสักครู่ให้ GitHub Pages อัปเดต แล้วเปิดเว็บไซต์แบบ Ctrl+Shift+R เพื่อล้าง cache เก่า
3. เว็บไซต์ของคุณจะมีที่อยู่แบบ `https://ชื่อบัญชี.github.io/ชื่อ-repo/` — ดูที่อยู่ที่แน่นอนได้จาก repo บน GitHub → **Settings** → **Pages** (จะมีแสดงลิงก์ไว้ให้ตรงนั้นเลย) จดที่อยู่นี้ไว้ให้แน่ใจ เพราะต้องใช้ในขั้นตอนถัดไป (ตั้งค่าล็อกอินด้วย Google)

## ตั้งค่าล็อกอินด้วย Google

ระบบนี้เปลี่ยนจากการ "พิมพ์อีเมลเอง" (ไม่ได้ยืนยันว่าเป็นเจ้าของอีเมลจริง) มาเป็นการล็อกอินผ่านปุ่ม **Sign in with Google** จริง — ต้องสร้าง OAuth Client ID จาก Google Cloud Console ก่อน 1 ครั้ง ทำตามนี้:

1. ไปที่ [console.cloud.google.com](https://console.cloud.google.com) → ถ้ายังไม่มีโปรเจกต์ ให้กดสร้างโปรเจกต์ใหม่ (หรือใช้โปรเจกต์เดิมที่มีอยู่แล้วก็ได้)
2. ไปที่เมนู **APIs & Services** → **OAuth consent screen**
   - เลือก User type เป็น **External** แล้วกด Create
   - กรอกชื่อแอป (เช่น "Sheet Search"), อีเมลผู้ใช้งาน, อีเมลติดต่อ แล้วกด Save and Continue ไปจนจบ (ขั้นตอน Scopes และ Test users ข้ามได้ ไม่ต้องเพิ่มอะไร)
   - **หมายเหตุ:** ถ้าปล่อยแอปไว้ในสถานะ "Testing" (ไม่กด Publish) จะมีเฉพาะอีเมลที่เพิ่มไว้ในหน้า "Test users" เท่านั้นที่ล็อกอินผ่านปุ่มนี้ได้ ถ้าต้องการให้ทุกคนใน `ALLOWED_EMAILS` ล็อกอินได้โดยไม่ต้องเพิ่มเป็น Test user ทีละคน ให้กด **Publish App** ในหน้านี้ (สถานะจะเปลี่ยนเป็น "In production" — จะมีคำเตือน "Google hasn't verified this app" โผล่ตอนล็อกอินครั้งแรก ซึ่งเป็นเรื่องปกติสำหรับแอปภายในที่ไม่ได้ยื่นขอ verify เพิ่มเติม ผู้ใช้กด "Continue"/"ไปที่...(ชื่อแอป) (ไม่ปลอดภัย)" ผ่านไปได้ปกติ)
3. ไปที่เมนู **APIs & Services** → **Credentials** → กด **+ Create Credentials** → **OAuth client ID**
   - Application type เลือก **Web application**
   - ตั้งชื่อได้ตามใจ (เช่น "Sheet Search Web")
   - ที่ **Authorized JavaScript origins** กด **+ Add URI** แล้ววาง origin ของเว็บไซต์คุณ (จากขั้นตอนที่ 3 ด้านบน) โดยตัดส่วนท้ายที่เป็นชื่อ repo ออก ใส่แค่ `https://ชื่อบัญชี.github.io` (ไม่มี path ต่อท้าย ไม่มี `/` ปิดท้าย)
   - ไม่ต้องกรอก Authorized redirect URIs (เว้นว่างได้ เพราะใช้วิธีแบบปุ่ม ไม่ใช่ redirect)
   - กด **Create** จะได้ **Client ID** ยาวๆ ลงท้ายด้วย `.apps.googleusercontent.com` มาแสดง — คัดลอกไว้
4. นำ Client ID ที่ได้ไปวางไว้ 2 ที่:
   - `frontend/config.js` → ตัวแปร `GOOGLE_CLIENT_ID`
   - Apps Script → **Project Settings** → **Script Properties** → เพิ่ม property ชื่อ `GOOGLE_CLIENT_ID` ค่าเดียวกัน
5. ตรวจสอบว่า Script Property `ALLOWED_EMAILS` มีอีเมล Gmail ของทุกคนที่ต้องการให้เข้าใช้งานได้ (คั่นด้วย comma) — คนที่ไม่มีชื่อในนี้ ล็อกอินผ่าน Google สำเร็จแต่ระบบจะปฏิเสธไม่ให้เข้าใช้งาน
6. อัปโหลดไฟล์ `frontend/` ขึ้น GitHub Pages ใหม่อีกครั้ง (ทับของเดิม) แล้ว Deploy Apps Script เป็น New version ใหม่อีกครั้ง (ตามขั้นตอนที่ 1 ข้อ "เมื่อแก้โค้ดในอนาคต") จากนั้นเปิดเว็บไซต์แบบ Ctrl+Shift+R ก็จะเห็นปุ่ม "Sign in with Google" แทนช่องกรอกอีเมลแบบเดิม

**หมายเหตุ:** ถ้าเว็บไซต์เคยจำอีเมลเดิมไว้ (ล็อกอินอัตโนมัติแบบเงียบๆ ผ่าน Google One Tap) แต่บัญชีนั้นถูกถอดออกจาก `ALLOWED_EMAILS` แล้ว ระบบจะขึ้น error และกลับไปที่ปุ่ม Sign in with Google ให้เลือกบัญชีอื่นแทน

## API ที่ใช้

ทุก action ต้องแนบ `&key=รหัสลับ` เสมอ

| Action | ตัวอย่าง URL | คืนค่า |
|---|---|---|
| เข้าสู่ระบบด้วย Google (จริง) | `?action=loginGoogle&credential=<ID token จาก Google>&key=...` | `{ ok, message, email }` — ตรวจ token กับ Google จริง แล้วเช็คกับ `ALLOWED_EMAILS`; ไม่ต้องส่ง `email` แยกมา (ไม่ใช้ต่อ) |
| รายชื่อไฟล์ทั้งหมด | `?action=books&key=...` | `{ ok, books: [ชื่อไฟล์, ...] }` — เร็วมาก ไม่แตะเนื้อหาในชีต |
| เพิ่มไฟล์ใหม่เข้าระบบ | `?action=addBook&name=ชื่อที่จะแสดง&sheetUrl=ลิงก์หรือID&key=...` | `{ ok, message, books }` — ทดสอบเปิดไฟล์จริงก่อนบันทึกเสมอ |
| สร้างไฟล์ Google Sheet ใหม่ทั้งไฟล์ (ยังไม่มีมาก่อน) | `?action=createBook&name=ชื่อไฟล์ใหม่&sheetName=ชื่อแท็บแรก(ไม่จำเป็น)&key=...` | `{ ok, message, books, bookName, url }` — สร้างไฟล์ใน Google Drive ของบัญชีที่รัน Apps Script แล้วเพิ่มเข้าระบบให้อัตโนมัติ |
| เอาไฟล์ออกจากระบบ | `?action=removeBook&name=ชื่อไฟล์&key=...` | `{ ok, message, books }` — บันทึกไว้ในถังขยะไฟล์ก่อนเสมอ ไม่ได้ลบไฟล์ Google Sheet จริง |
| ดูถังขยะไฟล์ | `?action=bookTrash&key=...` | `{ ok, items: [{id, name, sheetId, removedAt}] }` |
| กู้คืนไฟล์จากถังขยะ | `?action=restoreBook&id=...&key=...` | `{ ok, message, books }` |
| รายชื่อแท็บของไฟล์ | `?action=sheets&book=ชื่อไฟล์&key=...` | `{ ok, sheets: [{book, name, rowCount}], updatedAt }` |
| ข้อมูลทั้งแท็บ (ตารางเดียว) | `?action=sheet&book=ชื่อไฟล์&name=ชื่อแท็บ&key=...` | `{ ok, headers, rows, updatedAt }` |
| ค้นหาในไฟล์ที่ระบุ | `?action=search&q=คำค้นหา&book=ชื่อไฟล์&key=...` | `{ ok, results: [{book, sheet, row, cells}], truncated, updatedAt }` |
| ค้นหาเฉพาะแท็บเดียว | `...&book=ชื่อไฟล์&sheet=ชื่อแท็บ&key=...` | เหมือนด้านบน แต่เจาะจงแท็บ |
| ชื่อคอลัมน์ของแท็บ | `?action=headers&book=ชื่อไฟล์&sheet=ชื่อแท็บ&key=...` | `{ ok, headers: [...] }` |
| เพิ่มแถวข้อมูลใหม่ | `?action=add&book=...&sheet=...&data=<JSON>&key=...` | `{ ok, message, row }` |
| ลบแถวข้อมูล | `?action=deleteRow&book=...&sheet=...&row=เลขแถว&key=...` | `{ ok, message }` — บันทึกสำเนาไว้ในถังขยะก่อนลบเสมอ |
| แก้ไขแถวข้อมูล (ทั้งแถวหรือแค่บางคอลัมน์ เช่น สถานะ) | `?action=updateRow&book=...&sheet=...&row=เลขแถว&data=<JSON>&key=...` | `{ ok, message }` — เขียนทับเฉพาะคอลัมน์ที่ส่งมาใน data เท่านั้น บันทึกค่าเดิมไว้ในถังขยะก่อนเขียนทับเสมอ |
| ลบคอลัมน์ทั้งคอลัมน์ | `?action=deleteColumn&book=...&sheet=...&column=ชื่อคอลัมน์&key=...` | `{ ok, message }` — บันทึกสำเนาไว้ในถังขยะก่อนลบเสมอ |
| ดูรายการในถังขยะ | `?action=trash&book=...&key=...` | `{ ok, items: [{id, deletedAt, type, sheetName, columnName, preview}] }` |
| กู้คืนรายการจากถังขยะ | `?action=restore&book=...&id=...&key=...` | `{ ok, message }` — เพิ่มข้อมูลกลับเข้าชีตจริง (ท้ายชีต) แล้วลบออกจากถังขยะ |

## หมายเหตุ

- แท็บที่อยู่ใน `HIDDEN_SHEETS` (ในโค้ดคือ `'ชีต12'`) จะไม่ถูกดึงมาแสดงหรือค้นหาเลย ใช้ร่วมกันทุกไฟล์ **นอกจากนี้ แท็บที่ถูกซ่อนไว้จริงในตัว Google Sheets เอง (คลิกขวา > ซ่อนชีต) จะไม่ถูกดึงมาแสดงเช่นกัน โดยอัตโนมัติ ไม่ต้องเพิ่มชื่อในโค้ด**
- ฟอร์ม "เพิ่มข้อมูล" จะสร้างช่องกรอกให้เหมาะกับแต่ละคอลัมน์อัตโนมัติ: คอลัมน์ที่ชื่อมีคำว่า "วันที่" หรือ "date" จะได้ปฏิทินเลือกวันที่ ส่วนคอลัมน์ที่ตั้ง Data Validation แบบ "เลือกจากรายการ" ไว้ในชีตอยู่แล้ว จะได้ dropdown ตามตัวเลือกจริงในชีต ไม่ต้องตั้งค่าซ้ำฝั่งเว็บ
- ผลการค้นหาจำกัดไว้ที่ 200 แถวต่อครั้ง แก้ได้ที่ `SEARCH_RESULT_LIMIT`
- มี cache 5 นาที (`CACHE_SECONDS`) แยกตามไฟล์+แท็บ ถ้าแก้/ลบข้อมูลผ่านหน้าเว็บ ระบบจะล้าง cache ของแท็บนั้นให้อัตโนมัติ แต่ถ้าไปแก้ข้อมูลตรงในชีตเองโดยไม่ผ่านเว็บ ต้องรอ cache หมดอายุ
- **การลบแถว/ลบคอลัมน์จะบันทึกสำเนาไว้ในถังขยะก่อนลบเสมอ** กู้คืนได้ผ่านปุ่ม "🗑 ถังขยะ" บนหน้าเว็บ ข้อมูลที่กู้คืนจะถูกเพิ่มกลับเข้าไปท้ายชีตปลายทาง (ตำแหน่งเดิมเป๊ะๆ คืนให้ไม่ได้ ถ้าแถว/คอลัมน์อื่นมีการเปลี่ยนแปลงไปแล้วหลังจากลบ) ถังขยะเก็บประวัติล่าสุดไว้สูงสุด 200 รายการต่อไฟล์ (ตั้งค่าที่ `TRASH_MAX_ENTRIES`) เก่ากว่านั้นจะถูกลบทิ้งถาวรแบบกู้คืนไม่ได้อีก
- ถังขยะเก็บอยู่ในแท็บที่ชื่อ `_Trash` ซึ่งถูกซ่อนอัตโนมัติในแต่ละไฟล์ (สร้างขึ้นเองครั้งแรกที่มีการลบข้อมูล) ไม่ต้องไปยุ่งกับแท็บนี้เอง
- ปุ่ม "จัดการคอลัมน์" จะขึ้นให้กดก็ต่อเมื่อเลือกแท็บใดแท็บหนึ่งแล้วเท่านั้น (เลือก "ทั้งหมดในไฟล์นี้" จะไม่ขึ้น เพราะการลบคอลัมน์ต้องระบุแท็บเดียวชัดเจน)
- เพิ่มไฟล์ใหม่ในอนาคตได้ผ่านปุ่ม "+ เพิ่มไฟล์ใหม่" บนหน้าเว็บโดยตรง ไม่ต้องแก้ไฟล์ `Code.gs` หรือ Deploy ใหม่อีกต่อไป — รายชื่อไฟล์ตอนนี้เก็บอยู่ใน Script Properties ของโปรเจกต์ (key: `SPREADSHEETS_JSON`) ไม่ใช่ค่าคงที่ในโค้ด
- **ข้อควรรู้เรื่องสิทธิ์:** ทุกคนที่มีรหัสเข้าถึง (ACCESS_KEY) สามารถเพิ่ม/เอาไฟล์ออกจากระบบได้ผ่านหน้าเว็บ เหมาะกับทีมที่ไว้ใจกัน — การเพิ่มไฟล์ใหม่จะทดสอบเปิดไฟล์จริงก่อนบันทึกเสมอ (ถ้าบัญชีที่รันสคริปต์นี้ไม่มีสิทธิ์เข้าถึงไฟล์ที่วางลิงก์มา จะเพิ่มไม่สำเร็จ) ส่วนการเอาไฟล์ออกเป็นแค่เอาออกจากรายการที่เว็บนี้รู้จัก ไม่ได้ลบไฟล์ Google Sheet จริงแต่อย่างใด
